## 🎯 Что делает каждый файл

### Документация

1. **CI_CD_GUIDE.md**
   - Полное объяснение концепций CI/CD
   - Как работает процесс от начала до конца
   - Объяснение Docker-контейнеров
   - Разница между первичными и генеральными пайплайнами
   - Ответы на все ваши вопросы

2. **DOCKER_GUIDE.md**
   - Практические команды Docker
   - Как собрать и запустить контейнер
   - Решение типичных проблем

3. **QUICK_START.md**
   - Пошаговая инструкция по настройке
   - Чеклист готовности
   - Решение проблем

### Docker файлы

4. **Dockerfile** (в каждом микрофронтенде)
   - Multi-stage build для оптимизации
   - Сборка React приложения
   - Nginx для раздачи статики
   - Готов к production

5. **.dockerignore**
   - Исключает ненужные файлы из образа
   - Ускоряет сборку
   - Уменьшает размер образа

6. **docker-compose.yml**
   - Запуск всех микрофронтендов одной командой
   - Удобно для локальной разработки

### CI/CD пайплайны

7. **.github/workflows/ci.yml**
   - **Первичный пайплайн**
   - Запускается на каждый PR
   - Проверяет: lint, type-check, build
   - Быстрый (2-5 минут)

8. **.github/workflows/cd.yml**
   - **Генеральный пайплайн**
   - Запускается после merge в main
   - Создает Docker-образы
   - Публикует в GitHub Container Registry
   - Готов к развертыванию

## 🔄 Процесс работы

### При создании Pull Request:

```
1. Разработчик создает PR
   ↓
2. Запускается CI пайплайн (ci.yml)
   ↓
3. Проверки:
   - ESLint
   - TypeScript type check
   - Build
   ↓
4. Если все ✅ → можно мержить
   Если ❌ → нужно исправить
```

### После merge в main:

```
1. Код смержен в main
   ↓
2. Запускается CD пайплайн (cd.yml)
   ↓
3. Этапы:
   - Повтор всех CI проверок
   - Сборка Docker-образов
   - Публикация в GitHub Container Registry
   - (Опционально) Развертывание
   ↓
4. Готово! Образы доступны для использования
```
